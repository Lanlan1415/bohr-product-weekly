# 交付物骨架（引言与相关工作写作）

/app/output/ 下的标准布局（文件名可按契约字段名调整，但 result.json 中
如实指向）：

```
/app/output/
  manuscript.md              # 成稿：引言 + 相关工作（可编辑，含 [S#] 与对比表）
  evidence_map.md            # S1..Sn 登记 + 论断映射 + 缺口/贡献对照 + 待确认
  structure_check_report.md  # structure_check.py 输出
  result.json                # 契约字段透传 + 诚实 status
```

## manuscript.md 骨架

```markdown
# 引言与相关工作

## 研究背景
<领域脉络 1-2 句 [S#] → 具体问题定义 → 技术约束（有来源）>

## 相关工作
<分组依据一句：按 问题设定/方法路线/数据与评价 分组>
<组 1：论点句 + 组内比较 [S#][S#]>
<组 2：论点句 + 组内比较 [S#][S#]>

| 工作 | 方法 | 数据 | 结论 | 局限 |
|---|---|---|---|---|
| S1 | <短句> | <短句> | <短句> | <短句> |

<读表结论 1-2 句：共性限制是什么——缺口的引子>

## 研究空白
1. <（来源类型：共同限制/未覆盖场景/冲突结论）缺口陈述 [S#]；反例界定：
   哪些部分解不构成填补、为什么；边界：本文不承诺解决的相邻问题>
2. <……>

## 本文贡献
<总起一句：针对上述缺口，本文……>
1. <贡献 1：做了什么（对应缺口 1；证据：图/表/节）>
2. <贡献 2：……（对应缺口 2；证据：图/表/节）>

## 参考文献（如任务要求）
<按任务指定格式著录；本技能阶段可保留 [S#] 映射，元数据见 evidence_map>
```

## 写作要求

- 成稿保持任务指定的语言与引用制式；[S#] 与 evidence_map 严格一致。
- 缺口与贡献均用有序列表，条数相等；每条贡献含证据指针。
- 对比表维度 ≥3；每格为可核对短句，禁「效果好」「方法先进」类空词。
- 若任务要求 docx：先生成 md，用 office-renderer 转 docx 并渲染 PDF
  预览一并交付。
