# 要素齐全性清单与评分锚点（引言与相关工作写作）

交付前逐项勾选。每条标注对应评分维度（题面 §2），未勾项必须在 result.json 的
uncertainty 中说明原因。

## A. 契约与交付（任务完成度 15 分）

- [ ] A1 result.json 的 `case_id` 与 case.json 一致
- [ ] A2 `output_contract` 声明的全部原始字段透传（字段名一字不差）
- [ ] A3 status 诚实；sources / uncertainty / change_log 齐全
- [ ] A4 成稿为可编辑文本，语言、引用格式、篇幅符合 task.md 约束
- [ ] A5 先落盘过 partial（证据表 + 分组表 + result.json 草稿）再迭代

## B. 四段齐全且承接（任务完成度 / 结果完整性 5 分）

- [ ] B1 研究背景：从领域脉络落到**具体问题**与技术约束，无空转口号
- [ ] B2 相关工作：按问题/方法路线**分组**，组间有比较维度，非逐篇罗列
- [ ] B3 研究空白：由 B2 已引文献的缺口推出，每条带反例界定
- [ ] B4 贡献：逐条对应 B3 缺口，每条有证据指针（图/表/节）
- [ ] B5 四段顺序正确、互相指涉（缺口引用对比表，贡献引用缺口）

## C. 转述与空白正确性（结果正确性 15 分）

- [ ] C1 对他人工作的转述与材料中可得内容一致，无拔高/贬损/张冠李戴
- [ ] C2 引用元数据（作者、年份、来源）与文献库登记一致，无幽灵条目
- [ ] C3 每条空白能指出推导来源（共同限制/未覆盖场景/冲突结论 三类之一）
- [ ] C4 贡献表述不超出本文实际方法与结果，无「首次」「远超」类无据断言
- [ ] C5 作者判断类断言已明确标注（「我们认为」「作者判断」）

## D. 覆盖完整性（结果完整性 5 分）

- [ ] D1 材料库中的关键工作、代表性工作、近期进展均已覆盖或说明取舍理由
- [ ] D2 每条登记来源（S#）要么被引用，要么在取舍说明中解释未用原因
- [ ] D3 对比表维度 ≥3（方法/数据/结论/局限），覆盖各主要路线
- [ ] D4 必要字段齐全：每篇被引工作有作者（或 S# 可查）、年份、来源

## E. 可核验性（结果可核验性 5 分）

- [ ] E1 正文每个 [S#] 在 evidence_map 有登记行（structure_check.py 验证）
- [ ] E2 论断→[S#] 映射表逐条可查；分组依据写在相关工作开头
- [ ] E3 缺口推导过程在 gap_list.md 留有痕迹；贡献-缺口对照表可查
- [ ] E4 structure_check.py ERROR=0，WARN 已处理或写入 uncertainty

## F. 增益与证据（使用增益 25 分 / 创新增益 15 分）

- [ ] F1 保留中间产物（source_cards、rw_table、gap_list、contributions），
  写作与核对分离，可独立复核
- [ ] F2 相对基础 Agent 的改进点可对照：分组 vs 罗列、缺口有推导 vs 凭空、
  贡献有证据指针 vs 口号
- [ ] F3 方法说明（本 Skill 文档）可被他人在同类任务上复用

## G. 诚实与异常（可靠体验 10 分）

- [ ] G1 材料不足、文献库为空、原文不可得、格式未知等情形分别说明
- [ ] G2 无编造文献、无编造数据、无新增材料外事实
- [ ] G3 待确认清单每条有处置建议
