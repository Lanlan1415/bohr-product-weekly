## §1 漏斗结构判定（立得住）

漏斗四层缺一不可，且必须**逐层收窄、互相指涉**：

1. **领域与脉络**：2–4 句，指出本研究所属的真实研究脉络（哪条路线、哪个
   社区），每句挂 [S#]。禁止无引用的口号句。
2. **具体问题与技术约束**：从领域收到**一个**可操作的问题，写明约束条件
   （数据规模、资源、场景、指标），约束须有来源或来自本文材料。
3. **研究缺口**：由第 2 层已引文献的限制推出（推导规则见 §4），每条缺口
   带反例界定。
4. **本文贡献**：逐条对应缺口，每条挂证据指针（图/表/节）。

判定：任一层缺失、顺序颠倒、层间无指涉（缺口不引用相关工作、贡献不引用
缺口）均为不合格。structure_check.py 检查齐全性、顺序与贡献-缺口数量对应。

## §2 论点优先的文献综合（分得清）

**组织单位是论点，不是文献**。步骤：

1. 从 source_cards（每篇 S# 的 问题设定/方法路线/数据与评价/结论/局限）
   归纳 2–4 个**论点/路线分组**（如「基于规则的方法」「基于预训练模型的
   方法」）；
2. 每个论点一段：先给论点句（这组工作共同主张/解决了什么），再用若干
   [S#] 佐证，**同组内比较取舍**（A 用 X 换来 Y，B 反之）；
3. 段首或相关工作开头写明分组依据（按问题设定 / 按方法路线 / 按数据与
   评价方式，三选一为主），分组依据需能被复核；
4. 转述每篇工作时必须写清：结论 + 适用条件 + 局限，三者来自材料，材料
   未述的标「材料未述」，不脑补。

**禁止形态**：「S1 做了……。S2 做了……。S3 做了……。」逐篇摘要拼接；
按时间顺序罗列而不比较；一组只有一篇文献却声称「一类方法」。

## §3 相关工作对比表

- 维度至少覆盖 **方法 / 数据 / 结论 / 局限** 中 3 维（structure_check.py
  检查表头）；行 = 被引工作（S#），可再加「问题设定」「适用条件」列；
- 每格写**可核对的短句**（来自 source_cards），不写「效果好」「方法先进」
  这类无信息词；
- 表后必须有 1–2 句**读表结论**：从表中看出了什么共性限制——这句话就是
  缺口的引子；
- 正文转述与表格一致，不允许表里说「仅限英文」正文写「多语通用」。

## §4 研究缺口推导与反例界定（说得实）

缺口只允许从三类来源推出（每条标注属于哪类）：

1. **共同限制**：已引文献共享的假设或约束（如「均假设标注数据充足」）；
2. **未覆盖场景**：已引工作均未触及但本文问题需要的场景（如「均未处理
   低资源语种」）；
3. **冲突结论**：已引工作结论相互矛盾、尚未裁决（如「S3 报告提升，S5
   在相同基准上报告无提升」）。

**反例界定**（每条缺口必写，防止把「没人做过」误当缺口）：

- 写明**什么不算本文缺口**：已有哪些部分解、为什么它们不构成填补
  （「S2 虽处理低资源，但依赖双语词典，未覆盖无词典场景，故缺口仍成立」）；
- 写明**缺口的边界**：本文不承诺解决的相邻问题（「本文不解决跨模态
  迁移，该方向留待后续」）；
- 找不到反例界定 = 缺口未站稳，宁可降级为「潜在方向」并标注作者判断。

禁止：凭空断言「尚无研究关注 X」（检索范围之外不可知）；把「方法可以
更好」这种无限适用的愿望当缺口。

## §5 贡献表述与证据对齐（对得上）

- 每条贡献 = **可核对表述** + 缺口编号 + **证据指针**（图/表/节，来自
  claim_pool，即本文材料中真实存在的图表与结果）；
- 贡献数 == 缺口数，一一对应；多对一时合并缺口或拆分贡献；
- 措辞与证据强度匹配：材料显示提升 2 个点就写「提升 2 个点」，不写
  「显著优于」「远超」；「首次提出」只有材料明确支持时才可用；
- 贡献只承诺引言层面可兑现的内容；实验细节留给正文，不在引言编造数字。

### §5.1 相邻结果边界界定（neighboring result-table bounds，v2）

与最相近工作比较时，必须给出**双方的结果区间**而不是方向性口号：

1. 从 claim_pool 定位与本文**最相近的 1–2 篇工作**（同任务/同基准/同数据
   设定）在材料中报告的结果数值区间；
2. 本文对应结果区间与之**并置**：「S4 在 X 基准上报告 0.78–0.80；本文为
   0.81–0.83（表 2）」——区间两端都要能在材料中找到出处；
3. 区间重叠或材料中没有可比数值时，只写「与 S4 相当（见表 2）」，
   **禁止**「显著优于」「远超」「大幅提升」；structure_check.py 与
   selfcheck.py 对无数值的比较断言给 WARN；
4. 缺口段如涉及效果断言（「现有方法在 X 上不足」），同样要有最相近工作的
   数值边界作支撑，否则降级为作者判断并标注；
5. 边界界定也是防夸大的自检：写下区间后，措辞强度不得超过区间所显示的
   差距。

## §6 引用覆盖与元数据

- 覆盖三层次：**奠基/关键工作**、**代表性工作**（各路线至少一篇）、
  **近期进展**（材料库中最新）；缺任一层次需在取舍说明中解释（如
  「材料库无近二年文献」）；
- 每个 [S#] 在 evidence_map 登记（作者、年份、来源、材料定位）；正文
  出现的 [S#] 不允许未登记（幽灵引用），登记未引用的要么补引要么写明
  未用原因；
- 引用元数据只取自材料库登记信息；目标格式（GB/T 7714 / APA 等）以
  task.md 为准，未知时用中性学术格式并在 uncertainty 说明；
- 正式参考文献条目著录规范可复用 managing-citations-references 技能的
  规则；本技能只管「引谁、挂哪、是否覆盖」。

## §7 反模式清单（写了等于没写）

1. **空转背景**：「近年来 X 受到广泛关注」无引用无具体问题。对策：§1，
   每句挂 [S#]，三句内落到具体问题；structure_check.py 自动 WARN。
2. **摘要拼接**：相关工作逐篇罗列无分组无比较。对策：§2 论点先行 +
   §3 对比表。
3. **无源缺口**：「现有方法效果不佳」——不引文献、说不出哪条限制。
   对策：§4 三类来源 + 反例界定。
4. **口号贡献**：「本文方法简单有效，具有重要的理论意义与应用价值」。
   对策：§5，每条贡献挂证据指针，structure_check.py 无指针即 WARN。
5. **张冠李戴**：把 S3 的结论安到 S5 头上，或拔高材料中的结论。
   对策：source_cards 先抽取后写作，转述只许用卡片内容。
6. **幽灵/闲置引用**：正文 [S7] 未登记；登记了 S9 全文未引。对策：
   structure_check.py 双向核对。
7. **贡献-缺口断裂**：3 条缺口 5 条贡献，对应关系靠猜。对策：
   §5 数量对齐 + 每条注明对应缺口编号。
8. **编造文献或数据**：材料库没有的经典论文「凭常识」补引。红线！
   只许用材料库条目；缺口推导受限时标「[材料不足]」。

## §8 成稿优先工作流（manuscript-first，v2）

**先写完整初稿落盘，再对照检查迭代精修**——不要逐段拼到最后才成文：

1. 素材抽取（source_cards / claim_pool）完成后，**立即一次性写出**覆盖
   漏斗四段的完整初稿 `/app/work/draft_v1.md`：每段先求完整通顺，拿不准的
   局部标「待核」，但不留空段；
2. 初稿即诚实 partial：900 秒预算内任何时刻中断，都有一篇可读全稿 +
   证据表可交付（finalize 韧性）；
3. 之后的缺口反例界定、相邻结果边界、贡献对齐都是对 draft_v1 的**定点
   回改**，每次回改后重跑 structure_check.py；
4. 精修轮次按收益排序：先修 ERROR（结构/幽灵引用/对应关系）→ 再修
   空转句与比较断言数值边界 → 最后做语言润色；
5. 反模式：逐段反复打磨导致预算耗尽时只有两段成品——成稿优先正是为了
   消除这种失败形态。
