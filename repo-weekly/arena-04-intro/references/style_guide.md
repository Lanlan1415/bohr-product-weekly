# 风格规范（引言与相关工作写作）

## 1. 文体与人称

- 中文学术文体：陈述句为主，避免口语（「搞」「弄」「大大提升」）与营销语
  （「重磅」「颠覆性」）；英文对应 formal academic register。
- 人称：中文用「本文」「我们」之一，全稿统一；英文用 "we" 或被动语态，
  不混用 "the authors" 与 "we"。
- 介绍本文贡献用现在时/完成时（「本文提出……」「we propose …」）；
  转述他人工作用过去时或现在时，全稿统一（「S2 提出了……」）。

## 2. 转述动词（按证据强度选词，不夸大不贬损）

| 强度 | 中文 | 英文 | 适用 |
|---|---|---|---|
| 强 | 证明了、表明（有数据支撑） | demonstrate, show | 材料中有明确实验结论 |
| 中 | 提出、采用、报告 | propose, employ, report | 中性转述 |
| 弱 | 认为、主张、推测 | argue, claim, suggest | 材料中为他人观点/推测 |

- 转述不得升格：材料中是「推测」就写「推测」，不写成「表明」。
- 比较他人工作用中性措辞（「在 X 条件下受限」），不用「存在严重缺陷」
  「完全无法」等贬损语。

## 3. 断言与来源标注

- 事实断言句末挂 [S#]（顺序编码制则挂 [n]，以任务要求为准），引用紧跟
  论断句而非段末堆叠。
- 作者判断类断言必须显式标注：「我们认为……」「作者判断，待证」。
- 数值断言（「提升 2.1 个点」）必须来自本文材料（claim_pool）并挂证据
  指针（图/表/节）；材料没有的数值一个都不许出现。
- 「首次」「远超」「显著」仅当材料明确支持时使用；统计显著性须有检验
  报告，否则写「提升 N 个点」。

## 4. 结构与格式

- 标题层级 ≤3 级；漏斗四段标题用任务语言的习惯命名（中文：研究背景 /
  相关工作 / 研究空白 / 本文贡献，或按 task.md 指定）。
- 缺口与贡献用有序列表逐条呈现（机器可核对一一对应）；每条 1–3 句。
- 对比表用 markdown 表格；表头维度词用 方法/数据/结论/局限（英文稿
  Method/Data/Findings/Limitation），便于 structure_check.py 识别。
- 中文与西文/数字混排时两侧空一格；标点全角（中文稿）半角（英文稿）
  各自统一。
- 篇幅以 task.md 为准；未指定时引言+相关工作合计中文 1500–2500 字或
  英文 700–1200 词，相关工作占比不超过六成。

## 5. 引用格式一致性

- 引用制式（顺序编码 [n] / 著者-出版年 (Author, Year)）以 task.md 为准，
  全稿只用一种；
- 文末参考文献条目著录规范（GB/T 7714 / APA / Vancouver）按任务指定，
  字段缺失只标注不编造；本技能成稿阶段用 [S#] 占位并在 evidence_map
  给出完整元数据，最终替换为目标制式编号。
