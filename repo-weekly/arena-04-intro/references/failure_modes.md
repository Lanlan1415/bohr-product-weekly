# 基础 Agent 典型失败模式与对策（引言与相关工作写作）

直接支撑「使用增益/创新增益」：每条给出 表现 → 后果 → 本 Skill 对策。

1. **空转背景**
   - 表现：开头三段「近年来……受到广泛关注」「随着深度学习的蓬勃发展」，
     无引用、无具体问题，读完不知道论文要解决什么。
   - 后果：「立得住」零分；评审在第一段失去耐心。
   - 对策：funnel_writing_guide 第 1 段三步写法；structure_check.py 检测
     无引用的口号句并 WARN；背景段必须落在具体约束上。

2. **相关工作逐篇罗列**
   - 表现：「S1 做了 A。S2 做了 B。S3 做了 C。」按文献逐篇摘要拼接，或按
     年份流水账，无分组、无比较维度。
   - 后果：「分得清」失败；读者看不出格局，缺口无从推出。
   - 对策：method_rules §2 论点优先综合；source_cards 先抽取后归纳分组；
     对比表（方法/数据/结论/局限）强制同维度比较。

3. **无源缺口 / 伪缺口**
   - 表现：「据我们所知尚无研究关注 X」，既不引文献也不说明检索依据；
     或把「方法还能更好」这种永远成立的愿望当缺口。
   - 后果：「说得实」失败；审稿人随手一篇反例即可推翻。
   - 对策：method_rules §4——缺口只允许从共同限制/未覆盖场景/冲突结论
     三类来源推出，且每条必写反例界定（什么不算缺口）。

4. **口号式贡献**
   - 表现：「本文方法简单有效，具有重要理论意义与应用价值」，无证据指针、
     与缺口不对应、贡献条数与缺口条数对不上。
   - 后果：「对得上」失败；贡献无法核对兑现。
   - 对策：method_rules §5——每条贡献挂缺口编号 + 图/表/节证据指针；
     structure_check.py 校验贡献-缺口数量一致与证据指针存在。

5. **转述失真（张冠李戴 / 拔高）**
   - 表现：把甲文的结论安到乙文头上；材料里是「在小数据集上略有提升」
     被写成「显著优于所有基线」。
   - 后果：「结果正确性」一票否决级失分，且构成对他人工作的误述。
   - 对策：source_cards 中间文件先抽取「结论+适用条件+局限」，写作只许
     用卡片内容；style_guide §2 转述动词按证据强度选词。

6. **引用覆盖失衡与幽灵引用**
   - 表现：只引材料库中 2–3 篇，遗漏关键路线与近期进展；或正文出现
     [S7] 而证据表只登记到 S5；或凭「常识」补引材料库中不存在的经典文献。
   - 后果：「对得上/完整性」失分；补引材料外文献直接触碰编造红线。
   - 对策：method_rules §6 三层覆盖（关键/代表性/近期）+ 取舍说明；
     structure_check.py 双向核对 [S#] 登记；文献只许来自材料库。

7. **写作与核对混在一起，无法复核**
   - 表现：一口气直接出成稿，事后无法说明某句转述来自哪篇材料的哪部分。
   - 后果：「可核验性」失分；出错后只能整篇重写。
   - 对策：主流程把 source_cards / rw_table / gap_list / contributions
     作为可机器校验的中间产物先行落盘，写作与核对分离。

8. **材料不足时硬凑**
   - 表现：文献库只有 2 篇却写出「大量研究表明」；缺口缺乏依据时编造
     更激进的断言；期刊格式未知时擅自发明引用格式。
   - 后果：可靠性与诚实性失分。
   - 对策：SKILL.md §7 异常处理——如实写「材料库仅 N 篇」，缺口受限处
     标「[材料不足]」，格式未知用中性格式并写入 uncertainty。
