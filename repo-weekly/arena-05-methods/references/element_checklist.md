# 六类要素齐全性清单与评分锚点（写作09｜方法与实验章节写作）

交付前逐项打勾。每条标注其支撑题面的哪个评分点（实际效果 40 / 使用增益 25 / 创新增益 15 / 可靠体验 10 / 生态贡献 10）。

## A. 契约与交付结构（实际效果·任务完成度）

- [ ] 已读 `/input/case.json`，`result.json` 含 `case_id`，且 `output_contract` 声明的**全部原始字段**逐字透传（字段名一字不差）；
- [ ] `/app/output/` 含：方法章节成稿（.md 或 .tex，按任务语言/格式）、`param_table.md`、`evidence_map.md`、`result.json`；
- [ ] `result.json` 含 `status`（success/partial/failed 且与实情一致）、`sources`、`uncertainty`、`change_log`；
- [ ] 曾尽早落盘过一版六类要素齐全的诚实初稿（change_log 可见迭代记录）。

## B. 要素①步骤（实际效果·结果完整性）

- [ ] 实验/流程步骤按时间或逻辑顺序编号排列，每步含：输入、操作、输出、判断条件；
- [ ] 没有把多步操作压成一句（反例见 method_rules.md §7）；
- [ ] 预处理、训练、评测三段流程分开描述，条件不串台；
- [ ] 关键判断点给出量化阈值（如"收敛判据：验证集损失连续 10 轮不下降"），而非"至收敛为止"。

## C. 要素②实验设置（实际效果·结果正确性）

- [ ] 硬件写明型号与数量（如 GPU 型号、卡数），材料有的话；
- [ ] 软件栈写明名称+版本号：框架、关键库、CUDA/驱动、操作系统；
- [ ] 运行环境可重建：依赖清单/容器镜像/环境文件位置已指向具体材料 [S#]；
- [ ] 随机种子、重复次数、每次运行时长写明；未提供的标 [待确认] 而不是略去。

## D. 要素③参数（实际效果·结果正确性；创新增益·方法改进）

- [ ] 参数表列齐全：名称、当前值、被覆盖值、单位、作用对象、来源（文件:位置）、所属阶段/运行；
- [ ] 阶段级出处：每个参数标注属于哪个阶段/哪次运行（预处理/训练/评测，run #），跨阶段同值注明"共用"；
- [ ] 观察值 vs 配置值取舍留痕：正文用日志/命令行观察值时，被覆盖的配置旧值仍在参数表"被覆盖值"列与冲突记录中保留（两侧同时保留）；把旧值写成"本次采用"前必有实际加载证据，否则标 [待确认]（method_rules.md §2.7）；
- [ ] 正文数值与参数表逐一相等；`param_check.py` 退出码 0（无冲突）；
- [ ] 成稿中每个数值都能在材料中找到出处（--strict 下 param_check 无"无来源"项）；
- [ ] 单位全程一致（如学习率不一处写 1e-3 另一处写 0.01；温度不一处 K 一处 ℃）；
- [ ] 超参数与默认值的区分写清：哪些是调过的、哪些是沿用默认的（材料可查的话）；
- [ ] 曲线/指标数值只写材料给出的首尾值或明确极值点并挂行号来源，不目测中间点。

## E. 要素④数据集与划分（实际效果·结果完整性）

- [ ] 数据集名称、版本、规模（样本数/大小）写明；
- [ ] 预处理方式写明（清洗、归一化、增广），来源挂 [S#]；
- [ ] 划分比例与随机方式写明（如 8:1:1，seed=42 的随机划分/按时间划分）；
- [ ] 各子集用途写明（哪份用于训练/调参/最终报告），训练集不混入评测结论。

## F. 要素⑤对照（实际效果·结果正确性）

- [ ] 每个基线写明对象+版本/出处，不是"与现有方法相比"；
- [ ] 对照条件是否同预算（同数据、同算力、同调参预算）有明确说明；
- [ ] 评价指标定义写清（公式或出处），统计方式写清（均值±方差、显著性检验方法、重复次数）；
- [ ] 结论与证据匹配：没做的实验不写"优于"，只引用材料中真实存在的对比结果。

## G. 要素⑥复现与限制（实际效果·结果可核验性；可靠体验·异常处理）

- [ ] 复现清单五项齐全：代码版本/获取方式、环境、运行命令、数据获取方式、预期产物；
- [ ] 限制条件指向具体失效场景（如"本方法在样本量 <100 时方差显著增大，见日志 S3"），无套话；
- [ ] 材料缺口与待确认项在成稿末尾和 evidence_map.md 双处显式列出；
- [ ] 没有为填缺口编造数值、版本或引文。

## H. 来源与可核验（实际效果·结果可核验性）

- [ ] 每个含事实/数值的句群末尾挂 `[S#]`，S# 全部在材料登记表中存在（selfcheck.py 强制）；
- [ ] evidence_map.md 中每条关键论断可逐条回溯到材料具体位置；已支持行均有证据编号（E# → S#+位置），交付前按编号抽查可回溯；
- [ ] 修改记录（change_log）反映真实迭代，不是事后补写。

## I. 可靠与生态（可靠体验 10 / 生态贡献 10）

- [ ] 材料缺失、配置冲突、参数无来源、版本不明四种情形各有处置记录；
- [ ] 脚本失败时已手工执行同等检查并在 change_log 说明；
- [ ] 参数表模板、句式库、清单可脱离本案例被他人复用。

## J. 覆盖与篇幅核对（实际效果·结果完整性；WARN 级）

- [ ] 六类要素在成稿中各有**实质段落**而非一句话带过（selfcheck.py 对过短/缺席要素给 WARN 提示，不判 FAIL）；
- [ ] 成稿篇幅与任务要求相称：过短（如全文不足 300 字却声称六类齐全）或某要素明显单薄时，selfcheck WARN 提醒，人工复核是否补写或如实标注；
- [ ] 负路径自测已执行：至少一个"必须被拒绝"用例（正文参数与材料冲突未标注 / result.json 缺契约字段）确认被脚本拦截（退出码 1），用例放 /app/work 并标注合成。
