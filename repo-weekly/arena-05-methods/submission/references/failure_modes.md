# 基础 Agent 在本题的 9 类典型失败与对策（写作09）

以下失败模式来自基础 Agent 在"方法与实验章节写作"任务上的常见表现，每条给出本 Skill 的对策及其落地位置。这些对策直接支撑"使用增益/创新增益"评分。

## F1 顺手续数：为段落通顺编造数值

- **表现**：材料里只有学习率和 batch size，成稿却"补齐"了 weight decay=1e-4、warmup=1000 步等读上去合理的值。
- **对策**：来源标注强制规则（method_rules.md §3）+ `param_check.py --strict` 把"成稿数值无材料来源"列为 FAIL；缺口一律标 [待确认]。

## F2 参数前后打架

- **表现**：正文写"batch size 32"，实验设置小节又写"每批 64 条"；或中文稿 0.001、英文稿 0.01。
- **对策**：参数表单一事实源（method_rules.md §2）+ `param_check.py` 跨材料、跨成稿交叉检测数值与单位冲突，退出码非 0 不交付。

## F3 配置与日志不一致时随手二选一

- **表现**：config.yaml 写 lr=1e-3、train.log 打印 lr=0.01，Agent 挑顺眼的写进正文，不记录另一个值。
- **对策**：冲突处置规则（method_rules.md §4）：日志实际加载值优先、两值都登记 evidence_map.md、判断不了标 [待确认]；change_log 记录取舍依据。

## F4 六类要素缺腿

- **表现**：只写步骤和参数，数据集划分、对照设置、复现信息整类缺席；或"复现性"只有一句"代码将开源"。
- **对策**：六类要素清单（element_checklist.md §B–G）逐类核查 + `selfcheck.py` 对六类关键词组做强制检查；复现清单六项逐条问（method_rules.md §6）。

## F5 多步操作压成一句

- **表现**："数据经清洗、去重、归一化后按 8:2 划分并输入模型。"——四个操作零细节，读者无法重做。
- **对策**：步骤判定标准（method_rules.md §1）要求每步含输入/操作/输出/判断条件；句式库（sentence_patterns.md §2）提供中英步骤展开句式。

## F6 条件串台

- **表现**：把训练条件、验证条件、测试条件揉在一段；用验证集调参却报告"测试集最优值"；基线用原文报告值却未说明数据规模不同。
- **对策**：骨架（templates/methods_skeleton_*.md）强制训练/验证/测试分段；对照写法规则（method_rules.md §8）要求同预算说明与统计方式。

## F7 限制条件写套话

- **表现**："本方法存在一定局限性，未来将进一步研究。"——不指向任何失效场景。
- **对策**：style_guide.md §6 + element_checklist.md §G 要求限制落到具体场景（样本量阈值、分布外数据、硬件依赖），并挂材料依据；写不出场景就列为待确认项。

## F8 交付不可核验

- **表现**：只交成稿，无来源映射、无修改记录；result.json 缺契约字段或 status 一律 success；材料读不出时静默跳过。
- **对策**：evidence_map.md 逐条论断可回溯；`selfcheck.py` 强制 result.json 含 case_id/契约字段/status/sources/uncertainty/change_log 且 [S#] 标记已登记；材料缺失一律 partial 并在 uncertainty 说明（SKILL.md 异常处理）。

## F9 只抽取不溯源：静态配置当事实、旧值冒充"本次采用"

- **表现**：脚本静态扫一遍 config/code 就按配置值行文；config 里被命令行/日志覆盖的旧值（如 lr=0.001）被写成"本次采用"，日志里的真实观察值（0.01）被丢弃；参数不分阶段混为一谈。本题对照实验显示：只做静态抽取 + 以运行为依据的行文、但没有出处分级与冲突处置，得分显著更低。
- **对策**：观察值 vs 配置值取舍规则（method_rules.md §2.7）——日志/命令行观察值进正文、被覆盖旧值保留在参数表"被覆盖值"列（两侧同时保留）；阶段级出处（§2.8）逐参数标注所属阶段/运行；`param_check.py` 的后缀别名归一化把"本次采用学习率为 <旧值>"这类写法也归入规范键并判冲突 FAIL（拦截记录见 change_log）；YAML 锚点/空值按语义处理不误报。
