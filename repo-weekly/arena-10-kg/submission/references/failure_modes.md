# 基础 Agent 在本题的典型失败模式与对策

逐条对应"使用增益/创新增益"评分点：每条失败模式都是本 Skill 相对基础 Agent 的可证明改进。

## FM1　凭常识补全实体与关系

**现象**：论文只做了电导率测试，基础 Agent 却给材料节点挂上"石榴石型结构""对空气敏感"等常识属性，甚至建出论文没做的方法边。
**后果**：图谱看似丰富，实体却不可回查——"抽得准"直接丢分。
**对策**：本 Skill 的"证据先行"约束——没有 quote 不建边；`unlinked_mentions.md` 收留想建但缺证据的关系；`graph_check.py` 强制三证据字段非空。

## FM2　关系方向写反或共现当成因果

**现象**："A 优于 B" 与 "B 优于 A" 混写；同段出现的两种材料被连成 outperforms；综述转述被标成本文实验结果。
**对策**：schema 明确每个关系的主宾角色（method_rules §2）；证据强度三级标注；建边后回读"主语-关系-宾语"是否就是原文陈述。

## FM3　重复节点与错误合并（对不齐）

**现象**：`LLZO`、`Li7La3Zr2O12`、`llzo` 三个节点并存；或反过来，把两篇论文的不同样品合并成一个节点，电导率数值被"合取平均"成一个编造结论。
**对策**：归一化规则 + 合并三条件 + "Sample 永不跨篇合并"红线（method_rules §3）；`graph_check.py` 的规范名撞车与别名冲突检测兜底；合并与不合并决策都留痕。

## FM4　证据挂接形同虚设

**现象**：边的证据写"见原文第 3 页"（输入根本没有 PDF 页码）、quote 是改写而非原文、多条边共享一条万能证据。
**对策**：四要素证据规范（source_id/paragraph_id/quote/strength），quote 限 40 字逐字；selfcheck 与 graph_check 双重拦截空证据；摘要中证据可逐条抽查。

## FM5　两篇论文张冠李戴

**现象**：把 corpus-manifest 里第一篇的根 DOI/标题/作者套到第二篇；把同篇的 JSON 与 Markdown 当两篇独立证据刷"跨篇一致性"。
**对策**：第 1 步强制逐篇归属确认；source_id 一篇一号、同篇多格式共用；题面输入修订条款抄入 SKILL.md 异常处理。

## FM6　查询演示造假

**现象**：三个"查询"其实是重新读论文临时回答，答案里出现图文件中没有的边；或查询全是同一类型（都是"X 是什么"）。
**对策**：查询只允许从 CSV 取数，答案附涉及的 node/edge ID 清单；模板要求覆盖按实体查/按关系查/跨篇比较至少两类；图里没有的关系如实回答"无法确定"——这本身是题面要求的加分项。

## FM7　一次性憋大招，超时无交付

**现象**：基础 Agent 试图一次读完全部论文再成图，900 秒预算耗尽时 `/app/output/` 为空或只有半成品。
**对策**："先落盘小图再迭代"硬流程——第 3 步每读完一篇就更新 CSV 并过一次 graph_check.py；任何时候中断都有过了质量门的部分结果。

## FM8　增量更新推倒重来

**现象**：加入第二篇论文时重新编号全部节点，旧证据链全断；新结论直接覆盖旧结论，冲突消失。
**对策**：ID 只增不改、废而不删；冲突建 contradicts 边双挂证据；change_log 记录"新增/合并/冲突"三清单（method_rules §5.3）。

## FM9　无条件的比较结论（v2 新增）

**现象**：把"LLZO 对锂金属更稳定"建成 outperforms/more_stable_than 边却不记录比较条件；另一篇在不同温度/电流密度下的结果拿来直接对比，得出"两篇一致/矛盾"的伪结论。
**对策**：比较-条件门（method_rules §2）——比较类边 condition 列必填，graph_check.py 强制；阅读时把比较条件登记进对齐名册 §4；原文没给条件就不建边、记待确认。

## FM10　图谱交付即死档：不可交换、不可回导（v2 新增）

**现象**：只交 CSV（评审无法用图工具查看）；或手工另写一份 GraphML，属性对不上、导入丢边，无人发现；交付后文件被改动也无检测手段。
**对策**：graphml_roundtrip.py 导出 GraphML 并立即回导验证（CSV→GraphML→解析回比对，逐属性一致才通过）；--verify-only 做事后改动检测；CSV 与 GraphML 不一致时以 CSV 为准重新导出。
