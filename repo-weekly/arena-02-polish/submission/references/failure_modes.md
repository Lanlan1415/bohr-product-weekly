# 基础 Agent 在本题的典型失败模式与对策

逐条对应"使用增益/创新增益"评分点：每条失败模式都是本 Skill 相对基础 Agent 的可证明改进。

## FM1　限定词消失（最致命）

**现象**：摘要里 "LLZO **may** be a promising candidate" 润色后变成 "LLZO **is** a promising candidate"；"suggest" 升级成 "demonstrate"。
**后果**：结论被偷偷加强，"没改坏"整项失分，且人工极难逐句发现。
**对策**：软守恒清单（method_rules §1）——限定词/否定词计数变化由 `conservation_check.py` 自动 WARN，逐处人工核对并留痕；L1-L4 分级中"限定词不属于任何一级的可改对象"。

## FM2　数字与单位顺手改

**现象**：3.2e-4 被"四舍五入"成 3e-4；"25 °C" 被意译为 "room temperature"；0.32 eV 被换算成 kJ/mol。
**对策**：数字多重集硬守恒，任何差异即 FAIL；唯一例外（期刊要求）须"有意为之+依据"入 change_log。

## FM3　整段重写，无法回溯

**现象**：基础 Agent 输出"润色后全文"+一段笼统的"主要修改：提升流畅度"，没有逐句对照。
**对策**：交付物结构强制"润色稿 + 六要素逐条记录"；`selfcheck.py` 检查 ≥3 条编号条目与改前/改后对照字样。

## FM4　术语漂移

**现象**：引言写 "garnet electrolyte"，方法写 "LLZO"，结论又写 "lithium lanthanum zirconate"——同一概念三种写法在不同章节来回换。
**对策**：第 2 步先建 terms.txt 批准写法，L3 统一只许"未批准→批准"方向替换，守恒门按出现次数复核，术语链不断。

## FM5　引用与图表指向错位

**现象**：润色中重排句子导致 [12] 跟错论断；"as shown in Figure 1" 被改成 Figure 2；中译英时参考文献编号整体偏移。
**对策**：引用标记与图表/公式编号列入硬守恒，逐字比对；顺序类问题不改编号，写入待确认项。

## FM6　中式英语只改皮毛

**现象**：把 "play an important role" 换成 "play a significant role"——直译腔换了个词还是直译腔。
**对策**：style_guide §4 给出结构级改法（动词化、删套话、状语归位），并要求理由写清判定依据；"换一种说法掩盖"列入反模式。

## FM7　越权改内容

**现象**：发现原文数据前后矛盾，直接把数字改"对"；觉得结论太弱就补一句 "Therefore, X is the best choice"。
**对策**：职责边界写入 SKILL.md——语言问题动手，内容问题只记录：矛盾进 evidence_map 待确认项；新增结论属"材料外事实"，契约明令禁止。

## FM8　重复润色逐次漂移

**现象**：同一段落被要求润色三次，每次都比上一次更"漂亮"也离原文更远，三轮后限定词、数值口径全变。
**对策**：守恒基线固定为 original_snapshot.md（prepare 封存，不再改动）；每次运行都与基线比对，而不是与上一版润色稿比对。

## FM9　编辑记录免抄原文，锚定失效（v2 新增，冠军复盘的最贵教训）

**现象**：修改记录只写 "sentence_id: 7, 改为：……" 而不抄原句。句子切分版本一变、或记录与句子错位，修改就落到错误的句子上，甚至把 A 句的改法套到 B 句——没有任何机制能发现。
**后果**：某 77.7 分方案 v1.1 改 id-only 后得分 76.3→72.3，恢复抄原句锚定后回到 77.7（公开复盘数据）。
**对策**：锚定协议写入 method_rules §8——每条编辑记录先逐字抄原句再写改文；`verify.py` 空白宽容比对，锚定失败即拒绝；id-only 仅作宽容降级通道并记 WARN。

## FM10　违规编辑"只报告不回退"，交付后被静默篡改（v2 新增）

**现象**：检查脚本报告"数字不一致！"但润色稿原样交付——报告归报告，错误归错误；或者 finalize 之后有人手工"微调"了交付文件，无人复核。
**对策**：`verify.py` 违规编辑**自动回退**（句子保持原文，改动根本不会进入润色稿）；`finalize.py` 生成 `_manifest.json` 哈希基线，`audit.py` 做事后篡改检测 + 守恒复核 + 契约复核，任何 finalize 之后的改动都会 FAIL。
