# 基础 Agent 典型失败模式与对策（参考文献与引用管理）

直接支撑「使用增益/创新增益」：每条给出 表现 → 后果 → 本 Skill 对策。

1. **段末堆引用**
   - 表现：把 [1-8] 挂在段落末尾，段内多个论断实际只被其中一两条支撑。
   - 后果：评审无法判断哪条文献支撑哪句，「挂得对」零分。
   - 对策：method_rules §1 五类句型逐句扫描定位；引用紧跟论断句。

2. **删改后断号/错位**
   - 表现：删除一条文献或调换章节后，正文出现 [7] 而列表只到 [6]，或编号顺序
     与首次出现顺序不符。
   - 后果：「编得顺」失败，读者无法按号索骥。
   - 对策：citation_check.py 自动报告断号/错位；method_rules §3 整体重排算法
     + 旧号→新号映射写入 change_log。

3. **去重误并或漏并**
   - 表现 a：把同第一作者同年的两篇不同论文并成一条；表现 b：同一论文的中文
     版/英文版、arXiv 版/期刊版重复著录未合并。
   - 后果：引用计数错乱、文献表虚胖或丢文献。
   - 对策：dedupe_refs.py 三档判据 + 反并提示；合并决策逐对记录（method_rules §4）。

4. **编造缺失字段**
   - 表现：条目缺页码/年份/DOI 时「合理补全」，甚至生成形态逼真的假 DOI。
   - 后果：学术不端红线，「结果正确性」一票否决。
   - 对策：缺失只许显式标注（gbt7714_field_templates §10 约定表）；
     selfcheck 与人工复核双重把关；uncertainty 如实列出。

5. **格式转换丢字段**
   - 表现：BibTeX/RIS → GB/T 后只剩「作者. 题名. 年」，卷期页 DOI 类型标识全丢。
   - 后果：文献表不可用，需全部返工。
   - 对策：method_rules §5 必保字段清单 + 类型映射表；转换后跑 lint 核对。

6. **著者-出版年制年份错配**
   - 表现：正文 (Smith, 2020) 对应列表里 2019 的条目；同作者同年多篇未加
     a/b 后缀。
   - 后果：「对得上」失败，且人工极难逐条发现。
   - 对策：citation_check.py --style author-year 按（作者, 年）键交叉核对，
     同键多条目自动提示加后缀。

7. **中文条目著录西化**
   - 表现：中文文献用「et al.」、书名刊名加斜体标记、全半角标点混用。
   - 后果：不符合 GB/T 7714，格式项失分。
   - 对策：style_guide.md + citation_check.py lint（et al./标点混用自动 WARN）。

8. **幽灵来源与假核验**
   - 表现：来源映射里出现未登记的 [S#]；或声称「已联网核验全部属实」。
   - 后果：可核验性失分；无联网能力时属编造软件状态。
   - 对策：selfcheck.py 第 7 项幽灵 [S#] 检查；核验只做确定性项目，
     其余标「[待核验]」（method_rules §6）。

9. **把任务说明当材料**
   - 表现：依据 task.md 里的主题词臆造「该领域经典文献」补进文献表。
   - 后果：新增材料外事实，违反评测红线。
   - 对策：文献表只来自 /input 文献库快照；snapshot 先行，任何条目可回溯。
