# 原编号 ↔ 新编号双向映射表模板

只要发生过**插入 / 删除 / 合并 / 重排**中的任何一种，就必须交付本表，
使新编号能找回原编号（回溯），原编号能查到去向（追责）。填完后用
`scripts/mapping_check.py` 校验（函数性 / 无碰撞 / 连续性 / 与正文一致）。

## 模板

```markdown
# 编号映射表

| 原编号 | 新编号 | 去向 | 备注 |
| --- | --- | --- | --- |
| 1 | 2 | 保留 | 重排后后移 |
| 2 | 2 | 保留（合并保留条） | 原 [3] 并入本条 |
| 3 | - | 删除（并入新 [2]） | 同 DOI 10.xxxx/... |
| 4 | - | 删除（未被引用） | 正文无论断支撑 |
| 5 | 1 | 保留 | 提前至首次出现 |
```

也接受纯文本行形态：`3 -> 2 保留`、`4 -> - 删除`。

## 填写规则（双向可回溯）

1. **正向（原→新）**：原文献表的每一个编号都必须出现且只出现一次，
   去向三选一：`保留`（给新号）/ `并入新 [k]`（新号列填 -，备注写并入
   对象与判据）/ `删除`（新号列填 -，备注写理由）；
2. **反向（新→原）**：新文献表 1..N 每个编号恰好对应一个保留的原编号，
   不允许两个保留条目共用新号（碰撞），不允许跳号（断号）；
3. **与正文一致**：正文、图表注、附录中出现的每个 [n] 都必须是表中的
   保留新号；mapping_check.py --manuscript 可机器核对；
4. 本表与 evidence_map.md 的修改记录、result.json 的 change_log 互相
   印证：合并/删除的理由在三处措辞一致。
