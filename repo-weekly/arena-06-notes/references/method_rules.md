# 方法细则与判定标准（阅读10）

> 目录：1 章节对齐判定｜2 字段判定标准｜3 锚点格式规范（含 v2 区间定位与
> 契约草稿核对）｜4 分层摘要规则｜5 未报告与冲突标注｜6 多篇对比矩阵规则｜
> 7 反模式（写了等于没写）

## 1. 章节对齐判定

- 以 PDF 的**实际标题层级**为准：编号节（"3.2 …"）、命名节（"Discussion"）、
  无编号小节（加粗引导段）都算；页眉页脚不算。
- 判定合格：笔记章节摘要区的一级条目与论文实际章节一一对应、顺序一致；
  论文有而笔记没有的节必须显式说明（"第5节为附录指引，略"）。
- 判定不合格：把论文压成"背景/方法/结果/结论"四段而与原文章节对不上号。

## 2. 字段判定标准

| 字段 | 合格线 | 常见误判 |
|---|---|---|
| 研究问题 | 可用一句话复述且能在引言找到原句锚点 | 把"领域重要性"当成研究问题 |
| 方法与条件 | 方法名 + 关键参数/装置/样本量/统计检验 + 前提假设 | 只写方法名，丢了让结论成立的条件 |
| 数据与材料 | 来源、规模、时间/版本三要素齐全或逐项标"未报告" | 把"公开数据集"当完整描述 |
| 主要结果 | 数值带单位；区分主结果与附带观察 | 把作者展望写成实验结果 |
| 局限与适用边界 | 至少覆盖作者自述；读者发现的另标"（笔记作者注）" | 照抄"未来工作"冒充局限 |
| 可复用要素 | 给出名称+位置（锚点/链接）+用法一句 | 罗列"代码、数据"而无定位 |

## 3. 锚点格式规范（机器可校验）

统一写法：`[S<编号> <定位>]`，定位至少含下列一种，可组合：

- 页码：`p.3`（PDF 物理页）或 `第3页`；跨页 `pp.3-4`
- 章节：`§2` 或 `§2.1`（用论文自己的编号）
- 段落：`¶2`（该节内从上往下数第 2 段）
- 图表：`fig.2`、`表1`、`式(3)`、`附录A`

示例：`[S1 p.4 §2.1 ¶3]`、`[S1 fig.2]`、`[S2 表1]`。
规则：映射表与字段区的关键论断必须带定位锚点；只写 `[S1]` 视为笼统出处，
notes_check.py 判 FAIL。编号 S# 必须与 materials_register.md 一致。

### 3.1 v2 增补：区间定位与稳定原文定位符

- **行区间定位**：`L12-15`（或 `L12`）指抽取文本中的第 12–15 行，用于给出
  **精确的多行证据区间**；与页/节组合为"页+章节+行区间"复合锚点：
  `[S1 p.3 §3.1 L12-15]`。行号以第 2 步抽取出的文本文件为准（pdftotext/
  OCR 输出），同一次任务中行号口径必须一致。
- **稳定原文定位符优先**：章节号（§3.1）、图表号（fig.2、表1）、式号（式(3)）
  在 PDF 重排、分页变化后仍稳定，优先于单纯页码；页码与行区间作为精度补充，
  不单独使用。
- **复合定位建议**：关键论断锚点尽量含 ≥2 类定位（页/章节/段落/图表/行区间），
  notes_check.py 检查 7 统计复合锚点比例（WARN 级建议，不判 FAIL）。
- **章节完整性（chapter-complete）**：章节摘要必须覆盖论文**全部**实际章节；
  从略的节要显式写"§N 从略（原因）"，不得只覆盖部分章节而不说明。
  提供 --section-map 时 notes_check.py 检查 6 逐节比对（WARN 级）。

### 3.2 v2 增补：契约草稿核对（v3 起为建议性，不阻塞交付）

写入 `/app/output/result.json` 之前，先把草稿写到 `/app/work/result_draft.json`，
运行 `scripts/contract_check.py --case /input/case.json --draft ...` 核对
output_contract 全部原始字段就位、case_id 一致；缺字段能补则补一轮，
补不齐的记入 uncertainty/skipped_reason，然后照常落盘最终文件——脚本退出码
仅供定位问题，不作为交付门禁。摘录与数据核对（notes_check.py）建议先于
契约字段落盘（避免先写 result.json 再补内容），但其 FAIL 同样不阻塞交付。

## 4. 分层摘要规则

- 一句话摘要：主语=论文，谓语=做了什么，≤60 字，不含评价性形容词。
- 一段摘要：问题→方法→关键结果（带 1-2 个核心数值）→局限，≤250 字。
- 详细摘要：按论文章节顺序展开，每章 2-5 条要点，保留章节承接
  （"在 §2 数据基础上，§3 提出……"）。
- 三级摘要内容必须互相一致：详细版里的数值必须能在一一段版/字段区找到同源锚点。

## 5. 未报告与冲突标注

- 三级标注：**未报告**（原文确实没写）／**无法判断**（材料读了但信息不足）／
  **材料冲突**（两处原文互相矛盾）。
- 写法：`未报告（原文未给出样本量）`、`无法判断（图3无法解析）`、
  `材料冲突（正文 p.5 报 12.3，附录A 表A2 报 12.8，均照录）`。
- 禁止把"未报告"写成"无"或"没有该问题"——前者是原文没说，后者是事实断言。

## 6. 多篇对比矩阵规则

- 行=要素（研究问题/数据/方法条件/评价指标/主结果/局限），列=文献（S1、S2…）。
- 每格写法：≤40 字结论 + 锚点；该文献未涉及则写"未报告"。
- 矩阵之后必须有"分歧与互补"节：结论不同的要素列出各方锚点，不裁决胜负，
  只说明条件差异能否解释分歧。

## 7. 反模式（写了等于没写）

1. **通篇压缩摘要**：一段流畅文字覆盖全篇，无字段无锚点 → 对不上、找不回。
2. **笼统出处**：结论后挂 `[S1]` 或"（见原文）"→ 锚点无定位，核验者要重读全文。
3. **方法名打卡**："采用了深度学习与统计分析"→ 无条件、无参数，结论的前提丢失。
4. **未报告留白**：局限一节空着或写"无明显局限"→ 评审判为要素缺失。
5. **数值裸奔**："准确率提升了 12%"无单位语境无锚点 → 无法核验。
6. **图表虚指**："如文中所示"→ 必须落到 fig.N / 表N。
7. **同义条目刷屏**："CNN""卷积网络""convolutional network"分三条 → 知识点归并失败。
8. **摘要自我矛盾**：一句话摘要说"显著提升"，详细摘要写"差异不显著"→ 三级摘要未对齐。
