## 1. 实体 schema（贴合材料学科）

每个实体四元组：`{规范名 label, 类型 type, 别名 aliases[], 出现位置 mentions[]}`。
`type` 只能从下表选取（本案例未出现的类型不建空类）：

| 类型 | 定义 | 材料学科实例 | 判定要点 |
|---|---|---|---|
| Material | 具体材料/化学体系/器件结构 | Li7La3Zr2O12、NCM811、MAPbI3 薄膜 | 有确定化学式、牌号或明确组成的才算；"固态电解质"这类泛称不是 Material，除非原文把它当确定对象使用 |
| Method | 制备、表征、计算、实验方法 | 溶胶-凝胶法、XRD、DFT+U、EIS | 必须是论文中真实使用或明确讨论的方法；背景介绍里一笔带过的不建 |
| Task | 研究目标/应用场景 | 锂金属负极保护、全固态电池组装 | 来自原文的目标陈述，不自己概括拔高 |
| Metric | 性能指标及其定义 | 离子电导率（S/cm）、首周库伦效率 | 指标实体不带数值；数值挂在边属性里 |
| Claim | 论文的实验/计算结论 | "LLZO 在 25 °C 电导率 3.2e-4 S/cm" | 必须区分作者自述结论与他人转述 |
| Researcher | 研究者/团队/通讯单位 | "Zhang 等"、"本文作者" | 只在任务要求或消歧必需时建；不把参考文献作者批量建点 |
| Sample | 具体样品/批次/模型实例 | "本文 S-750 批次 LLZO"、"POSCAR-1 结构" | 跨篇对齐的关键：Sample 永不相合并（见 §3） |
| Condition | 实验/计算条件 | 25 °C、1 mA/cm²、PBE 泛函 | 作为边的属性优先；独立建点仅当多篇共享同一条件且需对齐 |

属性建议：Material 记化学式/体系；Method 记类别（制备/表征/计算）；Metric 记单位；Claim 记极性（支持/否定/不确定）。

## 2. 关系 schema 与方向约定

标准关系见 `references/predicates.txt`（机器校验清单），语义约定如下：

| 关系 | 方向 | 含义 | 证据要求 |
|---|---|---|---|
| uses | 主语=研究/方法，宾语=材料/方法 | 使用了某材料或方法 | 正文明确陈述使用 |
| prepares | 方法→材料 | 用该法制备了该材料 | "采用 X 法制备 Y"类陈述 |
| characterizes | 方法→材料/样品 | 用该表征手段分析 | 正文或图注明确 |
| has_metric | 材料/样品→指标 | 报告了某指标的数值 | 数值与单位进边属性 `value`/`unit` |
| outperforms | A→B | 在同一比较语境下 A 优于 B | 必须有同篇内的直接比较陈述，且注明比较条件 |
| more_stable_than | A→B | 稳定性优于 | 同上，"稳定"的定义照原文 |
| supports | 证据/结论→结论 | 支持 | 作者明确表述的支持关系 |
| contradicts | A→B | 与 B 矛盾 | 作者明确指出，或两篇结论在同一条件下数值/方向冲突（此时双挂证据） |
| compares | A→B | 被比较（无优劣结论） | 有比较行为但未下结论时用，不要升级成 outperforms |
| proposes | 研究者/论文→方法/结论 | 提出 | 区分"本文提出"与"文献[X]提出" |
| reports_value | 结论→指标 | 报告具体数值 | 边属性带 value/unit/condition |

**方向反了是最常见硬错误。** 建边后默念一遍 "主语-关系-宾语" 是否就是原文那句陈述。

**比较-条件门（v2 硬规则）**：凡 outperforms / more_stable_than / compares
边，必须在 `condition` 列标明比较条件（温度、组成、电流密度、测试协议等），
并在对齐名册 §4 登记出处。原文只比较没给条件 → 不建边，记入待确认；
建了空 condition 的比较边 → graph_check.py 判 FAIL。理由：脱离条件的
比较结论在跨篇对照时必然被误用——"A 优于 B"几乎总是"A 在条件 C 下优于 B"。

新增关系类型的流程：先查 predicates.txt → 确无合适项 → 在 change_log 登记新关系名与定义 → 加入本案例的 predicates 副本 → 再使用。禁止随手造近义关系（improves / enhances / boosts 并存）。

## 3. 实体消歧与归并规则

### 3.1 归一化（机器层，graph_check.py 已实现的等价规则）

NFKC 规范化 → 去首尾空白 → 压缩内部空白 → 大小写折叠。另加人工规则：

- 缩写 ↔ 全称：Li7La3Zr2O12 / LLZO / 锂镧锆氧 → 同一节点，规范名取**含化学式或信息最完整**的写法，其余进 aliases；
- 中英文：同一概念的中英文名归并，规范名按论文主要语言；
- 下标/线性化：JATS 把 Li₇La₃Zr₂O₁₂ 线性化为 Li7La3Zr2O12，视为同一写法；
- 希腊字母与符号：α/alpha、μm/um 按原文写法保留在 aliases，规范名选论文主流写法；
- 标点变体：sol-gel / sol–gel / sol gel 归并。

### 3.2 可以合并（必须同时满足）

1. 归一化名称相同，或一方是另一方在**同一篇或另一篇中明确写出的**缩写/别名（原文出现过 "……（缩写）" 或 "以下简称"类定义）；
2. 类型一致；
3. 合并依据写入 evidence_map：引用各自出处段落。

### 3.3 不得合并（题面红线，逐条对照）

- **Sample 永不跨篇合并**：两篇都说 "LLZO"，也是两个样品节点（label 加篇目后缀，如 `LLZO (S1 样品)`）；
- 不同论文的模型实例、数据集、实验条件各自独立；
- **实例级共享标识符规则（v2 强化）**：模型、数据集、样品、实验、条件类实例**仅当共享同一原文标识符**（原文给出的编号、批次号、DOI 子标识、数据集版本号）才可合并；仅名称相同不是依据，无共享标识符的候选一律不合并并在对齐名册注明"无共享标识符"；
- 仅因"都叫同一个通用方法/材料术语"而合并两篇的具体对象——禁止；
- 同名研究者：无确定同一性证据（单位、ORCID、自引链）时不合并；
- 拿不准时：**不合并**，并在 merge_decisions 记"候选未合并：理由"。错合并比重复节点危害更大，但重复节点会被脚本拦截，所以流程是：默认不合并 → 证据足够才合并 → graph_check.py 兜底查重。

## 4. 证据挂接规则

每条边四要素，缺一不可（graph_check.py 强制前三项非空）：

- `source_id`：材料登记表编号 S#，**一篇论文一个号**，同篇多格式（JSON/Markdown/XML）共用一个号；
- `paragraph_id`：组织方 JATS 段落 ID（如 `sec2-p3`）。本包**没有 PDF 页码**，自建分页不得标注为原 PDF 页；
- `quote`：≤40 字的原文逐字短引，能独立支撑该边；公式/上下标按线性化后的原文照抄；
- `evidence_strength`：`direct`（作者自述的本文结果）/ `cited`（作者转述他人工作）/ `inferred`（作者推测）。cited 与 inferred 边在摘要中单列，不得与 direct 混算。

未报告与冲突：论文没给的信息建"未报告"记录而不是编值；同篇自相矛盾或跨篇冲突，保留两边各自挂证据，在摘要"冲突与待确认"节并列呈现。

## 5. 图查询、GraphML 导出与增量更新

### 5.1 三个起步查询模板

1. **按实体查**："X 用了哪些方法/指标？" → 列出 X 的所有出边 + 每条证据；
2. **按关系查**："哪些材料被报告了指标 M？数值多少？" → 列出 has_metric 边子图 + value/unit/condition + 证据；
3. **跨篇比较/冲突**："两篇论文对 X 的结论是否一致？" → 并列两边证据，给出"一致/冲突/无法比较（条件不同）"的判定与理由。

每个查询的答卷必须含：结果子图（节点/边 ID 列表）、每条支撑证据的 quote、无法确定项说明。**查询只答图内有向可达的内容**：从起点沿边的方向遍历取数，不反向脑补、不推断图外科学事实；图里没有的就答"图中无此关系，无法确定"。

### 5.2 GraphML 导出与回导验证（v2）

- 交付时除 CSV 外导出 `graph.graphml`（graphml_roundtrip.py 自动生成，节点属性 label/type/aliases，边属性含全部证据列）；
- **可回导是硬指标**：脚本写出后立即重新解析，节点集、边集、全部属性与 CSV 逐项一致才算通过；不一致即 FAIL 并修复后再验；
- 交付后若怀疑 GraphML 被手工改动，用 `--verify-only` 与原 CSV 比对；
- GraphML 与 CSV 内容必须一致——CSV 是主交付，GraphML 是交换副本，二者不一致以 CSV 为准并重新导出。

### 5.3 增量更新（新论文加入时）

- node_id 只增不改、废而不删（废弃节点标 `deprecated:true`）；
- 新论文先走第 3-4 步：新实体拿新 ID；候选合并逐条裁决并留痕（保守增量合并：默认不合并，共享标识符或同篇定义句才合并）；
- 新旧结论冲突：建 contradicts 边双挂证据，不删旧边；
- 更新后重跑 graph_check.py、graphml_roundtrip.py 与图统计，把"新增/合并/冲突"三清单写进 change_log。

## 6. 反模式（写了等于没写）

| 反模式 | 为什么不行 | 正确做法 |
|---|---|---|
| "根据材料学常识，LLZO 属于石榴石型结构" 直接建边 | 常识补全，论文没说 | 只建原文有陈述的边；常识只能用于消歧参考，不进图 |
| 边证据写 "见论文 A 第 3 页" | 本包无 PDF 页码，且无法机器回查 | paragraph_id 用 JATS 段落 ID + quote |
| quote 改写或概括原文 | 无法逐字核对 | 逐字摘录 ≤40 字，删节用 … |
| 同段共现就建 outperforms | 共现≠比较结论 | 无明确比较陈述时建 compares 或不建 |
| 两篇的 "LLZO" 合并成一个节点并合取电导率 | 不同样品、不同条件，合成结论即编造 | 样品各自成点，数值各自挂边，冲突并列 |
| 合并依据写 "显然是同一物质" | 不可复核 | 引用两篇中各自的定义句作为依据 |
| 关系类型自由发挥（enhances/benefits/helps） | 图谱不可校验、不可复用 | 只用 predicates.txt 内关系，新增走登记流程 |
| 查询答案重新通读论文临时编 | 绕过图谱，查不到=答不出时露馅 | 只从图文件取数；图里没有就说"图中无此关系，无法确定" |
| 节点 ID 用含义名（如 `LLZO`） | 增量更新时改名即断链 | 用语义无关的稳定 ID（N001…），含义放 label |
| 摘要里写"共抽取约 50 条边" | 数字不可核 | 图统计由脚本/计数得出，与 CSV 行数一致 |
| "A 优于 B"建边但不写比较条件 | 脱离条件的比较结论跨篇必被误用 | 比较-条件门：condition 列必填，无条件不建边 |
| 只交付 CSV 或交付未验证的 GraphML | 图工具打不开/导入后丢属性无人发现 | graphml_roundtrip.py 导出即回导验证，一致才交付 |
